Tracking: #144 · Related feature: XPath inheritance #143 · Date: 2026-08-19

Detailed review

P0 — immediate-child boundary

Evidence. The revised foreach XPath has two alternatives: the original direct declaration and @extends equal to the name of a directly declared entity loot container. It does not recursively resolve extends. The regression test supplies DirectContainer, its child SyntheticBossContainer, and the grandchild TransitiveContainer. It asserts substitutes for the first two and no AutoLoot_TransitiveContainer. Recommendation. Keep this hard boundary. Impact. It satisfies #144 without making a potentially broad mod-behavior change on an assumption about deeper inheritance.

P1 — direct required data for every selected container

Evidence. Both selector alternatives now share direct Mesh and LootList requirements and still exclude LootList=cntDropBag. The synthetic fixtures cover a valid direct container, a valid direct container that extends another class, an immediate child, and direct or inherited candidates missing one required property. Recommendation. Retain the common direct-data contract. Impact. The template reads these values directly from $lootContainer; inherited or absent values would otherwise create a malformed item or a misleading fallback.

P1 — direct selector rather than transitive inheritance function

The associated #143 feature provides sm:inherited for effective, transitive values. It would therefore overmatch this issue’s requested scope. The direct XPath expresses the business boundary in the consumer’s own patch, while #143 remains separately useful for callers that truly need transitive effective-value semantics. Recommendation: accept this separation; it reduces hidden coupling between a bug fix and a still-incomplete developer-tool feature.

P2 — remove the obsolete expected warning

The common direct-data requirement skips vanilla twitch_crate_template before foreach materializes an item template, so its missing mesh no longer produces a warning. The matching ExpectedToLog declaration is removed and the all-version patch-application suite verifies that it stays unnecessary. This cleanup is coupled to #144 because it proves the strengthened selector is quiet, rather than preserving a warning whose cause no longer exists.

Naming — AutoLoot_<entity name>

The generated-item prefix says both what the item does and that it is derived rather than authored independently. The test asserts the complete AutoLoot_SyntheticBossContainer name. Recommendation: preserve this convention; replacing it with a generic word such as Generated would make source lookup harder.

Naming — AutoLootSubstituteFor

This property identifies the original runtime entity that an inventory item substitutes for. Its relationship wording distinguishes it from the item’s own LootList. Recommendation: keep it rather than abbreviating to an unclear term such as Source.

Naming — SyntheticBossContainer

The test name conveys that the document is synthetic, that it models a boss drop, and that it is a container. It does not memorialize the third-party mod that exposed the bug. Recommendation: retain this neutral fixture vocabulary so location, availability, and future content of external mods cannot affect the test.
