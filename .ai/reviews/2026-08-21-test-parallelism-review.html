Test infrastructure · 21 Aug 2026

Remove the false test scheduling barrier

The suite was already parallel, but one large build-path class stayed serial and the mod-logic collection could not start until every parallel collection finished. This change splits the isolated build-path checks and removes only the runner-wide barrier around mod-logic.

Measured cause

Configuration, not shared build state, caused the wait

Result: DisableParallelization = true made xUnit run all parallel-capable collections first and mod-logicmod-logic test 9.2 ms after the last BuildPathResolutionTests test ended.

The named mod-logic collection already keeps its own classes mutually serial. Its hosts load game and mod assemblies into private AssemblyLoadContext instances, so the extra runner-wide barrier did not protect those static values from another test collection.

Implementation

Expose the parallel work already present

  • Split the eleven build-path methods into six concern-named classes.
  • Keep the shared workspace harness in BuildPathResolutionTestBase.
  • Keep every mod-logic test in one serial collection.
  • Remove DisableParallelization = true so that collection can run beside unrelated work.

Verification

The structural change beats a larger thread pool
