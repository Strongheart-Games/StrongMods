Keep floating-point key-value data stable across server cultures

Issue #118

Problem

XmlKeyValueStore used the active process culture when it formatted and parsed float and double values. A server using a comma decimal separator could write 1,5, which is not portable to a server using the invariant decimal separator.

Change

The store now formats float and double values with invariant culture. Its generic reads also use invariant culture. Test-and-set uses the same stable text, so its comparison agrees with saved values.

Verification

The focused test sets the current culture to de-DE, saves 1.5d, checks that the stored text is 1.5, and reopens the store while that culture remains active.
