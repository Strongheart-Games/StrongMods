Subsystem

AuthZ — the invariant engine

One genuinely deep module anchors the mod: the abstract Invariant (five-member interface), with 19 concrete adapters collapsed under four shared bases so most rules are 3–5 lines. InvariantEngine dispatches per packet; NetPackageGuard is the adapter at the Harmony ProcessPackage seam. The friction is two seam leaks and verification that lives in deletable scratch space.

A forget hook on Invariant replaces the engine's concrete-type switch

Strongverifier: confirmed
AuthZ/InvariantEngine.cs:189-202AuthZ/Invariant.csAuthZ/Invariants/LifecycleInvariants.cs:37-39

Problem. ForgetClient switch-cases on two concrete invariant types to clear per-connection state; the Invariant interface says nothing about per-client state, so every planned family E rate rule must either edit the engine again or silently leak state on disconnect.

Deepen. A virtual per-client forget method on Invariant with a no-op default — OncePerConnection<T>.Forget already has the right shape, it just isn't reachable through the base. Roughly 10 lines.

  • locality: cleanup lives with its state
  • new stateful rules never edit engine
  • hook unit-testable directly
Verifier: since OncePerConnection<T> is generic, the engine cannot pattern-match a shared base to reach Forget — the virtual hook is the only clean shape, which strengthens the proposal. ForgetClient is confirmed wired to PlayerDisconnected.

Strongverifier: confirmed
AuthZ/Settings.cs:26AuthZ/Ownership.cs:34AuthZ/Invariant.cs:37Tests/Fixtures/ModLogicHost.cs

Problem. The only executing verification of AuthZ lives in .scratch/, which the repo defines as deletable at any time — and the interfaces are already test-shaped (Settings.Load is fully game-free; Holds and Ownership.Resolve take plantable game objects).

Deepen. Port the harness's game-free checks into Tests/ModLogic, then pin the two fixed Ownership.Resolve false positives (vehicle passengers, crossplay identity) as regression tests. No production code changes.

One configuration seam: thresholds through the same ApplySettings path as modes

Worth exploringverifier: confirmed
AuthZ/Settings.cs:24,39-48AuthZ/Invariants/DomainInvariants.cs:86AuthZ/InvariantEngine.cs:177-186

Problem. Modes are stamped onto invariants at startup; the one threshold instead flows through a bespoke Settings field read live through a global — a shallow trajectory that multiplies when threshold-heavy families C and E land.

Deepen. Per-invariant values keyed by invariant id, stamped through the existing ApplySettings seam; Settings keeps one generic parse behaviour. Do it before family C/E, not after.

ViolationLog: key per-client state by client identity; settle TotalFor

Worth exploringraised from Speculative
AuthZ/ViolationLog.cs:31,68-71,77-86

Problem. Per-client tallies are keyed by rebuilt human-readable strings, so Forget must reverse-engineer the key format with a prefix scan, and a rename orphans counters; TotalFor is interface surface with no caller.

Deepen. Key state by stable client identity (ClientNumber, the precedent OncePerConnection already uses); Describe stays a formatter. Wire TotalFor to its intended console command or delete it.

  • identity and display concerns separate

Defect found in passing: the key separator at ViolationLog.cs:31 and :79 is a literal raw NUL byte (0x00) embedded in the source — ripgrep classifies the whole file as binary and silently skips it, so the file is currently invisible to standard code search. Also: Describe uses playerName, empty before auth completes, so counters can orphan — a correctness defect, not a style concern. Any edit here should strip the NUL bytes.

Top recommendation

Zone registry: an instance module for sources → index → diff

It is the only candidate where the current shape has already produced a verified live bug: an admin editing strong_zones.xml on a running server silently erases every prefab-derived zone — trader no-claims, protected POIs — until restart. The deepening does not just fix the bug; it makes the bug class unexpressible at the interface (hot-reload becomes "rebuild from both current source lists"). The deletion test passes cleanly, the pure pieces move first inside the ~100-line workstyle, and the four enforcers gain one query interface with the diff finally testable without private reflection.

Cheapest Strong wins if you want tests before refactors: AuthZ's verification home and BountifulQuests' selection harness — both are pure additions to Tests/ModLogic with zero production changes, and both protect the two most recently changed subsystems in the repo. Two defects found in passing deserve attention regardless of any refactor: the raw NUL bytes in ViolationLog.cs (the file is invisible to ripgrep today) and the wrong-prefix diagnostics in QuestUnlockFixes/BloodRain.

Method. Seven explorer agents walked the subsystems weighted by recent change (the uncommitted AuthZ and BountifulQuests rewrites, the new Tests fixtures, the StrongMods patcher core, StrongUtils, the build system, and a 21-project cross-mod sweep). Every candidate then went to an adversarial verifier that re-read the cited files and tried to refute the friction, the deletion test, and any ADR-0001/0002 contact. 26 candidates survived: 17 confirmed, 9 weakened, 0 rejected; strengths shown are post-verification. Vocabulary per the codebase-design glossary: module, interface, depth, seam, adapter, leverage, locality. No repo files were changed.

Next step: pick a candidate to explore — constraints, the shape of the deepened module, what sits behind the seam, what tests survive. Nothing here proposes final interfaces yet.
