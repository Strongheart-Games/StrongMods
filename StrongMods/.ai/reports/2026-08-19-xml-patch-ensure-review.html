Developer-facing naming review

These are the names a mod author must type or understand. Both are coherent with the shipped model; neither merits a compatibility-breaking rename. This table is separate because names are part of the tool’s public API.

PriorityNaming decisionAssessment and recommendation
P3<ensure>Strong verb for an idempotent desired state; distinguishes this operation from procedural append and setattribute. Retain.
P3ensure-keyExplicitly scopes a reserved identity selector to this command and avoids a misleading generic key. Retain; document it as identity, not uniqueness.
P3position="append|prepend"Uses the patcher’s existing ordering vocabulary. Retain; the two options expose the real semantic choice without a new abstraction.

Contract: child elements, not attributes

The implementation rejects attribute-node targets and points authors to setattribute; the living specification explains why an XPath selecting @attr cannot discover absent attributes. This preserves a clean contract: <ensure> ensures child elements, while vanilla already upserts attributes. Focused failure tests cover both likely author spellings and assert the rewrite hint. Recommendation: leave this boundary intact unless a future use case cannot be expressed by setattribute.

Identity and ambiguity policy

A template uses tag plus name/class by default, or an explicit list in ensure-key. Multiple matching siblings generate a context-rich warning and are left untouched; malformed keys fail the whole block before mutation. The dedicated identity tests cover default keys, explicit keys, stripping the reserved attribute, nested templates, per-parent continuation, and fatal invalid templates. Recommendation: keep “do not guess” as the safety invariant; a last-match or first-match rule would be easier to write but unsafe for stacked effects and drops.

Name: <ensure>

The name describes the author’s intent—make a declared condition true—rather than exposing add-versus-merge mechanics. The implementation’s idempotency tests substantiate that meaning. It also does not overclaim replacement or synchronization, since the command never deletes undeclared children. Retain.

Name: ensure-key

The prefix makes the attribute’s ownership clear in a shared XML namespace and correctly ties it to the command. “Key” is accurate only as an identity selector: it can still match multiple existing siblings, which is why ambiguity is diagnosed. The current documentation makes that distinction; retain the term rather than introducing a longer synonym after release.

Name: position

append and prepend name concrete sibling placement, and the documentation explains that the setting applies only to new nodes and at every nesting level. This avoids calling a precedence policy a “mode.” Retain.
