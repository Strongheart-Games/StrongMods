Preserve StrongZone buff names in XML

Issue #119

Problem

Custom zones could have the buff tag but no configured buff name after XML loading. The buff manager then skipped the zone. Serialization also discarded a zone’s in-memory buff name.

Change

A zone’s buff XML attribute now fills and preserves BuffName.

The parser passes that attribute to the StrongZone constructor. The writer emits it when a zone has a buff name. The configured value stays available to the existing buff manager after a reload.

Verification

The regression test parses a buff-tagged zone, verifies its in-memory name, serializes it, and parses it again. The StrongUtils build passed. The focused StrongZoneTests suite passed 53/53.
