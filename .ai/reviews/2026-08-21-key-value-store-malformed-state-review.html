Recover from a malformed key-value store

Issue #124

Problem

The key-value store loaded persisted XML during startup. Invalid XML structure or an unsupported type value could throw from that load and stop the caller’s startup path.

Recovery policy

Malformed persisted state is logged and treated as an empty store. It does not stop StrongUtils startup.

The loader first validates all entries in a temporary dictionary. It replaces the live state only after the complete file is valid. A malformed file therefore cannot leave a partial in-memory store. The original file remains in place until a later write replaces it.

Verification

The regression test writes an unsupported type into kvstore.xml, runs KeyValueStore.Init, and verifies that it returns without an error and creates an empty store. The focused XmlKeyValueStoreTests suite passed 32/32.
