Make deleted-value events consistent

Issue #125

Problem

Remove reported the removed raw value in its Deleted event. Clear reported a null old value. A listener could not reliably learn the removed value without knowing which method changed the store.

Contract and change

Each Deleted event carries the value stored immediately before deletion and a null new value.

Clear now records each key and raw value while it holds the store lock. It clears and flushes once, then emits one event per recorded entry outside the lock. The interface documents this rule.

Verification

The strengthened regression test clears two entries and checks both old values, both null new values, and both Deleted change types. The focused XmlKeyValueStoreTests suite passed 31/31.
