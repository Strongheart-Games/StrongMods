Deploy logs describe actions, not target visits

A solution Deploy used to print at least one line for every code mod, modlet, and overlay, even when nothing changed. The revised output names only projects that copy or delete; an all-no-op solution emits one summary instead.

The observable contract

Project takes action

Retain the existing deployed (mirror) or overlaid line. Stale-file details remain immediately below it.

Direct project no-op

Print <Project> deployment is already up to date.; a direct invocation has no solution aggregator to speak for it.

Solution invocation

Suppress per-project no-op messages and the SDK’s unconditional Project -> DLL lines. If no project acts, print No projects needed deployment. once.

Action detection follows the copy semantics already in force

  • DeployFileChangeDetector uses the same size and last-write-time comparison as MSBuild Copy SkipUnchangedFiles="true". Mirror deploys also count stale destination files as actions.
  • Overlay protective copies reuse their existing absent-or-newer decision; mirrored scopes use the detector, and mirrored stale files remain deletions.
Solution boundary: after.StrongMods.sln.targets prepares a solution-Deploy-only marker directory and passes its path to projects. Acting projects leave a marker; the solution emits the summary only when none exist. Code mods silently reproduce the SDK assembly copy whose built-in target couples that required copy to the unconditional Project -> DLL message. Plain solution Builds are unchanged.
