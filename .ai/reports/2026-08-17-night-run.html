Nine defects, all verified against source

The key-value store writes numbers in the current culture

measured

3.5f stored under a de-DE locale persists as value="3,5" and reads back as 35 under en-US. No exception, no log line, no fallback — the caller gets a plausible wrong number, off by a factor of ten. Production is Linux and development is this Windows box, so the cross-locale case is the normal one.

StrongUtils/KeyValueStore/XmlKeyValueStore.cs · four writers use ToString("R"), Get<T> uses Convert.ChangeType, both current-culture. Fix is CultureInfo.InvariantCulture on both sides.

Dormant this season — the store has no live callers — which is exactly why it is cheap to fix now: no persisted files to migrate.

A buff-tagged zone declared in XML grants no buff

source-read

StrongZone.FromXml never reads or passes a buff name — the constructor's buffName parameter is filled only by the prefab path. So a zone declared in strong_zones.xml and tagged buff gets Buff == true and BuffName == null, and BuffManager.OnPlayerEntered returns early on exactly that pair. The zone is silently inert.

StrongUtils/StrongZones.cs:507 (parse) and :559 (ToXml, which has the mirror hole — a round trip loses a buff name that was set). One attribute each.

Harmony's own IL reader will not run on this test runner

PatchProcessor.GetOriginalInstructions routes through MonoMod, whose runtime detection refuses outright: PlatformNotSupportedException: CoreCLR version 10.0.10 is not supported, from MonoMod.Core.Platforms.Runtimes.CoreBaseRuntime.CreateForVersion. Measured on the pinned MonoMod.Utils 25.0.6 and on the newest published 25.0.14 — bumped, tested, reverted, so Tests.csproj is unchanged.

IlReader reads the bytes directly instead: GetILAsByteArray plus Module.ResolveMethod / ResolveField / ResolveType / ResolveString. Pure BCL — it removes a dependency rather than adding one. Fidelity is scoped to what a transpiler matches on; exception-handler regions are not reconstructed, and this IL is only ever read, never re-emitted.

Two harness bugs that looked like mod bugs

MethodType.Enumerator targets the generated MoveNext, not the declared method. StrongMods patches ModManager.LoadUiAtlases and LoadLocalizations that way. Resolving the declared method reaches only the stub that builds the state machine, so the mod's own “Cannot find any Exists() calls.” fired against a perfectly healthy transpiler. Fixed with AccessTools.EnumeratorMoveNext, the same hop Harmony makes.

MethodInfo.ToString() omits the declaring type. Both File.Exists and CaseSensitiveFilesystem.Exists render as Boolean Exists(System.String). StrongMods' transpilers swap one for the other, so a before/after diff on the bare string showed no change and reported a working transpiler as broken. A diff is only as good as its rendering, and an identical-signature swap is exactly what a transpiler often does.

Every harness carries a guard against asserting nothing

A rename that broke discovery would otherwise leave a suite green while checking nothing. The reference tests fail below 5,000 collected references; the transpiler tests fail below 13 discovered transpilers, and run an inert transpiler as a negative control to prove the harness can fail; the KnownDangling and ExpectedToLog lists are checked in both directions, so a declared exception that stops applying fails too. The linter ships 21 self-tests (-- --selftest).

Negative results

What turned out to be fine

A negative result is a result, and three of these save work you might otherwise have scheduled.

  • The localization header inconsistency is cosmetic, not functional. Five distinct headers across ten files, and by the loader's actual rules none of the differences changes what loads: the first column's name is overwritten with KEY before the check that reads it, so that check is dead code, and every other column matches vanilla case-insensitively — English and english are one column. Worth standardizing as a chore. Not a bug, and it should not be filed as one.
  • No mod's localization file is rejected today. A header column that is neither ^[A-Za-z]+$ nor context-prefixed makes the loader discard the entire file. All ten headers pass.
  • Every Extends chain resolves — 5,966 block and 1,139 item references, on both versions. The seed doc named StrongMining's nine vanilla parents as its top guard; this covers those and every other mod's.
  • No transpiler has lost its match point on either declared version, including DynamicLandClaimCount's, which its own source comment calls Linux-fragile. This runs on the Windows tree and cannot speak to Linux — but the Windows behavior is now pinned on both versions, which it was not yesterday.
